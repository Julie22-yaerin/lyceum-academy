The engines

Four endpoints. Each one a feature you'd otherwise spend a quarter building.

Every response is validated against a Pydantic schema before it leaves the harness. You render fields — you never parse Markdown, never regex a bullet list, never handle "the model added a preamble today".

POST /v1/reverse-build/evaluate

Reverse Build Auditor

A learner explains their solution in their own words. The auditor checks whether the reasoning is logically sound and whether they actually applied the concept the lesson was teaching — then returns the next state so your app can route them without writing a grading policy.

  • A right answer by broken reasoning does not pass. answer_correct and reasoning_sound are separate fields, and the verdict follows the reasoning.
  • Every flaw is located and typed: non-sequitur, circular, unjustified leap, wrong concept, scope error, algebra slip.
  • Tool-fidelity gate: catches the learner who counts rectangles instead of integrating — but passes a more sophisticated alternative method.
  • Returns HINTING / REVERSE_BUILD_RETRY / TRANSFER_TEST.
POST /v1/podcast

Podcast Producer

Study material in, a script a speech engine can read unedited out. Three formats matching how people actually listen: one-voice Storyteller, two-voice Explorers (expert + student), and Gladiators (structured, resolving disagreement).

  • TTS-safe by construction. No LaTeX, no markdown, no stage directions in spoken text — maths is verbalised ("d y by d x"), because a voice reads \frac aloud as letters.
  • Display LaTeX travels separately in on_screen_latex, so you can show and speak the same equation.
  • Listen-and-write: is_note_cue flags the lines worth writing down, plus a note checklist.
  • Hits a target duration from a real word count, not a guess.
POST /v1/feynman

Feynman Breakdown

One concept, rebuilt for a learner who lacks the vocabulary — simplify the language, never the physics. The commercial payload is knowledge_gaps: what to teach first, each with a diagnostic question whose wrong answer proves the gap is real.

  • Every analogy must declare where it breaks. Required field — an analogy without its limits installs a misconception.
  • Jargon dictionary for tooltips, plus the single most common wrong mental model, stated then corrected.
POST /v1/deconstruct

First-Principles Deconstruction

Take a theorem or system apart to its primitives, then show the ladder back up. Learners see the result was assembled, not handed down.

  • Building blocks flagged axiomatic vs derived — a derivation that hides its axioms is a magic trick.
  • Every rule carries its domain of validity; every step names the method it requires.
  • collapses_if: remove which assumption and the structure fails. Excellent exam-question material.

Plus POST /v1/validate — run the guardrails with no LLM call. Free, instant, no key required, so you can pre-check in your own UI before anything becomes billable.

Why licence instead of building

The prompt is the easy part.

Guardrails that protect margin

Three local gates, cheapest first, before a single token is billed: shape, prompt injection, STEM relevance. Unicode-normalised, so fullwidth confusables can't slip past. Deterministic and dependency-free — a guardrail that needs a network call to decide whether to make a network call isn't a guardrail.

Two guardrail profiles

A learner's hesitant, jargon-free answer must not be filtered as off-topic — it's exactly what the auditor exists to read. So student work gets a separate profile: injection still blocked, topic filter off. The detail that decides whether struggling learners can use your product at all.

Strict JSON, natively enforced

Structured output uses each provider's own mechanism — Gemini responseSchema, OpenAI json_schema — not a polite request in the prompt. We ship the schema transformers that reconcile their contradictory requirements, which is a day you don't lose to a 400 that looks like a prompt bug.

Failures are typed and bounded

Separate connect/read timeouts, exponential backoff with full jitter, Retry-After honoured but capped. 400/401/403 never retried — your key is wrong and hammering the provider just burns quota. Every error is JSON with a stable code.

A repair pass instead of a 502

If a response violates the schema, the harness sends it back with the validation errors and asks for a corrected document — preserving content, fixing structure. One extra call turns most would-be failures into a success. meta.attempts tells you when it fired.

BYOK — we never hold your key

Nothing reads a key from the environment. Your key arrives per request, is used once, and is dropped: never persisted, never logged unredacted, never echoed. Self-host and it never leaves your infrastructure. Your provider bill, your quota, your control.

PYTHON — as a library, no HTTP hop

from lyceum_harness import PodcastEngine, PodcastFormat
from lyceum_harness import GuardrailRejection, HarnessError

engine = PodcastEngine(api_key=user_key, provider="gemini")
try:
    script, meta = await engine.run(
        material, format=PodcastFormat.EXPLORERS, minutes=5,
    )
except GuardrailRejection as e:
    # Refused locally. Cost you nothing.
    return reject(e.reason)
except HarnessError as e:
    return retry_later(e.code)   # every failure is typed

for seg in script.segments:
    tts(seg.spoken_text)          # safe to speak verbatim
    if seg.is_note_cue:
        flash_write_prompt(seg.on_screen_latex)

FAQ

Do you see our API key or our learners' data?

No. The harness reads no key from the environment — yours arrives with the request, is used for that request, and is dropped. It's never persisted, never logged unredacted, never returned. If you self-host, neither the key nor the learner text touches our infrastructure at all. Logs record request id, provider, model, latency and outcome — not keys, not full learner input.

Are the guardrails a security boundary?

No, and we won't pretend otherwise. They're a cost-control and hygiene layer: heuristic pattern matching plus a relevance score. The real defence is that the prompts instruct the model to treat user text as data, and that defence-in-depth is what holds. If you're piping learner text into other systems, apply your own controls too.

Which LLM providers work?

Gemini and OpenAI are wired and tested on the four engines, with per-request model override so you can trade cost against quality without a new release. The Orchestrator (the skill router — see the showroom above) adds Anthropic natively: each provider needs a different structured-output mechanism under the hood, and that plumbing is already done. Azure OpenAI and Bedrock are a single branch in one function — ask, and it's a small piece of work rather than a redesign.

What happens when the model returns something malformed?

The harness sends the broken document back with its validation errors and asks for a corrected version, preserving content and fixing only structure. That rescues most cases. If the repair also fails you get a malformed_model_output 502 marked retryable — never a half-parsed object, and never a raw model dump.

Can the auditor be fooled by a confident wrong answer?

It's designed against exactly that: answer_correct and reasoning_sound are separate fields and the verdict follows the reasoning, so a right answer via a broken route cannot pass. It's still an LLM and it can be wrong. For high-stakes assessment, keep a human in the loop — we'll say that in the contract too.

Will it fail a student who solved it a smarter way?

No, and this is deliberate. Tool fidelity is about level, not conformity: a method of equal or greater sophistication passes and is recorded as an alternative. Only a lower-level dodge around the lesson fails. An evaluator that punishes elegance teaches learners to stop thinking.

Is the podcast output really safe to send to TTS?

That's the schema's central guarantee. Spoken text carries no LaTeX, no markdown and no stage directions, with maths verbalised, because a speech engine reads \frac aloud as letters. Display LaTeX travels in a separate field. It's asserted in the test suite, not just requested in the prompt.

Can we get our own schema fields, or Vietnamese output?

Yes to both on Studio and Source. The engines already answer in the language the learner wrote in. Extra fields, changed enums and curriculum-specific prompt tuning (Cambridge IGCSE / A-Level, IB, AP, national curricula) are part of a Studio engagement.

Is there streaming?

Not currently. These are structured single-shot documents and partial JSON isn't useful to a renderer. If you need SSE purely for perceived latency, say so — it's a reasonable addition.
